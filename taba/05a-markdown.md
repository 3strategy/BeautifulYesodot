כותבים מאמר כתוכן, בלי לעצב כל פסקה ב־HTML. Markdown הוא חלק נדרש מהאתר, ולא רק כלי לתיעוד קוד.

קישורי GitHub מפנים למאגר פרטי. המורה צריך להעניק הרשאת קריאה; אפשר ללמוד גם מהקוד המופיע כאן.

## מה נלמד

- לכתוב כותרות, רשימות, קישורים ותמונה.
- לבנות טבלה ולזהות את קובץ המקור.
- להפריד בין משמעות התוכן לבין עיצוב הדף.

## מתחילים מסונכרנים

פתחו את תיקיית הפרויקט הנכונה, בדקו שאין שינוי לא שמור והפעילו **Pull**. אם Git מציג התנגשות, פנו למורה; אל תמחקו עבודה ואל תבצעו Force Push.

## כותבים ומציגים תצוגה מקדימה

צרו `Content/care.md`. ב־VS Code הפעילו Open Preview to the Side; אם עובדים ב־Visual Studio אפשר לפתוח את קובץ ה־Markdown ב־VS Code לצורך תצוגה מקדימה. קישור שמתחיל ב־/ הוא ביחס לאתר ולכן ייבדק כשהתוכן יוצג באתר בפרק 6. כרגע הקובץ אינו דף אינטרנט פעיל.

כותרת ראשית מתחילה ב־# ורשימה ממוספרת מתחילה ב־1. רווח ושורה ריקה מפרידים בין בלוקים. אין צורך לכתוב div סביב כל פסקה.

## השינויים בקוד

### `RazorTaba/Content/care.md`

קובץ חדש. צרו את `RazorTaba/Content/care.md` והדביקו את התוכן הבא:

````markdown
# לפני שמאמצים, לומדים

בעל חיים צריך **טיפול קבוע**, סביבה מתאימה ותשומת לב.

## שלוש שאלות חשובות

1. האם יש לנו זמן לטפל בכל יום?
2. מה החיה צריכה לאכול?
3. מי יכול לעזור לנו כשאנחנו לא בבית?

| צורך | מה בודקים? |
| ---: | ---: |
| סביבה | מקום בטוח ומתאים |
| טיפול | מטפל אחראי וקבוע |

![איור של שועל](/images/fox.svg)

[חזרה לדף הבית](/)
````

## מריצים ובודקים

1. בתצוגה מקדימה יש כותרות, רשימה וטבלה.
2. הטקסט המודגש מופיע ללא סימני הכוכבית.
3. קובץ המקור קריא גם ללא תצוגה מקדימה.

## משימה אישית ובדיקת הבנה

כתבו מאמר אישי עם שתי כותרות משנה, רשימה וקישור למקור. הוסיפו תמונה בעלת טקסט חלופי. הסבירו מה שייך לתוכן ומה לעיצוב.

{: .box-success}
בסיום שינוי משמעותי: בדקו את ה־diff, בצעו Stage, כתבו הודעת commit שמתארת מה שיניתם, ובצעו Push. ודאו ב־GitHub שהשינוי הגיע. נדרשים לפחות 50 commits משמעותיים לאורך השנה, גם למי שעובד תמיד באותו מחשב נייד.

{: .box-note}
AI יכול לעזור להבין הודעת שגיאה ולנפות תקלה. אתם אחראים לכתוב, לבדוק ולהסביר את הקוד; אין להפעיל סוכן שיכתוב את הפרויקט.
