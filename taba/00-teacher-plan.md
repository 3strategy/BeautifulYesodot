## איזה אתר תרצו לבנות?

בחרו נושא שאתם רוצים להכיר לאחרים. למשל:

| נושא | פריטים באתר | למי משויך כל פריט? |
| ---: | ---: | ---: |
| בעלי חיים | חיות | מטפל |
| מוזיקה | שירים | אמן |
| משחקים | משחקי מחשב | סטודיו |
| ספורט | שחקנים | קבוצה |

כתבו שם לאתר ומשפט שמתאר מה ימצאו בו המבקרים. בהמשך תוסיפו לפריטים שלכם מידע, תמונות וטפסים.

## מה יהיה באתר שלנו?

- דף פתיחה ותפריט שמחבר בין הדפים.
- עיצוב עם CSS ו־Bootstrap שמתאים גם לטלפון.
- מאמרים ב־Markdown ותרשימים ב־Mermaid.
- רשימת פריטים שנשמרת במסד נתונים.
- טפסים להוספה, לעריכה ולמחיקה, עם בדיקת קלט.
- בשיעורי ההמשך: קשר בין פריטים, חיפוש, חשבונות והרשאות.

## איך עובדים עם ההדרכות?

קראו את מטרת השיעור, בצעו שינוי אחד והריצו את האתר. בקובץ חדש תראו את התוכן המלא; בקובץ קיים תראו diff שמציג את השינוי עם השורות שסביבו. סימני `+` ו־`-` אינם חלק מהקוד שמקלידים.

בסיום כל שלב בדקו את התוצאה והתאימו אותה לנושא שלכם. נסו להסביר מה השתנה בקוד ואיך הוא השפיע על האתר.

## שומרים את העבודה ב־GitHub

בתחילת העבודה פתחו את המאגר הנכון ובצעו Pull. לאחר שינוי משמעותי בדקו את ה־diff, בצעו Stage וכתבו הודעת Commit ברורה. לפני שמסיימים בבית או במעבדה בצעו Push ובדקו שהשינוי מופיע ב־GitHub. עבדו כך גם במחשב נייד אישי.

לאורך השנה נדרשים לפחות 50 commits משמעותיים. שמרו בכל commit שינוי שאפשר לתאר ולהסביר. אם מופיעה התנגשות, פנו למורה לפני שממשיכים.

## כשמשהו לא עובד

קראו את הודעת השגיאה, בדקו איזה קובץ ואיזו שורה היא מציינת והשוו לשינוי האחרון שלכם. אפשר להיעזר ב־AI כדי להבין שגיאה ולברר כיצד לבדוק אותה. כתבו ובדקו את התיקון בעצמכם; אל תפעילו סוכן שיכתוב את הפרויקט במקומכם.

## קהל, יעדים וזמן

- כיתה י׳, מתחילים ב־C#. תוכן ועיצוב נלמדים לפני תכנות שרת.
- בסיס: 36 שעות לימוד ליבה ועוד 9 להשלמות, בדיקות אישיות ופתיחת הרחבות.
- כ־30 שעות עבודת בית לפרויקט מתוך כ־90 שעות משותפות לפרויקט ול־C#; אין כאן דרישה ל־90 שעות פרויקט נוספות.
- תחילת השנה: HTML, עיצוב ותוכן. לולאות Razor רק אחרי תנאים ולולאות ב־C#; Animal ו־EF רק אחרי היכרות עם מחלקות ותכונות.
- אחרי כ־45 דקות HTML בעורך טקסט פשוט עוברים מיד ל־Visual Studio או VS Code ולפרויקט Razor רץ. עובדים בתחילה ב־HTML ו־CSS ומסבירים את תשתית Razor בהמשך.

## שלוש תחנות הצלחה

| תחנה | תוצאה | מעמד |
| ---: | ---: | ---: |
| אתר אישי | עיצוב Bootstrap, תוכן Markdown ותרשים Mermaid | הישג מוקדם; אינו מספיק להגשה שנתית |
| אתר עם נתונים | CRUD, ולידציה, תוכן אישי ובדיקת הבנה | הגשת ליבה תקפה |
| אתר מתקדם | קשר מטפל–חיות, סינון, חשבונות והרשאות | הרחבות לפי התקדמות הקבוצה |

אין לחסום את שיעור הנתונים בגלל עיצוב לא גמור. מספקים תבנית Bootstrap פשוטה ועובדת. עבודת הבית משפרת את אותו אתר; היא אינה פרויקט נפרד. נושאים אישיים נבחרים בפרק 2: מטפל–חיות, אמן–שירים, סטודיו–משחקים או קבוצה–שחקנים, עם הורה אחד לכל פריט.

## סביבת העבודה

הפרויקט ב־.NET 10 עם Razor Pages ו־SQLite. ב־Windows: Visual Studio עם רכיב פיתוח Web או VS Code עם C# Dev Kit. ב־macOS: VS Code עם C# Dev Kit. הפקודות מוצגות משורש המאגר. התקנות SDK וכלי עורך מתבצעות לפני המפגש ככל האפשר. המאגר נבדק בפועל ב־Windows; macOS הוא מסלול מתועד שעדיין דורש בדיקת הרצה במחשב מתאים.

כל תלמיד עובד במאגר משלו. [מאגר המורה הפרטי](https://github.com/3strategy/razortaba) אינו מאגר הגשה לתלמידים. הרשאת קריאה למאגר המורה ניתנת לפי החלטת המורה. בכל פרק יש קישור ל־commit מדויק ול־diff מהמצב שקדם לו. להשוואת גרסה ישנה אפשר להוריד ZIP של ה־commit לתיקייה נפרדת; אין צורך ללמד checkout או branches ואין לשנות לתלמיד את סביבת העבודה באמצע.

## Git הוא הרגל עבודה וראיה להתקדמות

לפחות 50 commits משמעותיים לאורך השנה. בתחילת מפגש במעבדה: פותחים את המאגר הנכון ובודקים מצב, ואז Pull. אחרי יחידת שינוי קטנה: בודקים diff, מבצעים Stage ו־Commit עם הודעה ברורה. בסוף בבית ובמעבדה: Commit לכל עבודה שנותרה ו־Push, ואז בדיקה ב־GitHub שהשינויים הגיעו. הכלל חל גם על מחשב נייד אישי.

המורה בוחן תאריכים, תוכן השינויים ורצף ההשקעה, ולא רק מונה סופי. היסטוריית Git היא מדד מרכזי למאמץ, ומצטרפת להסבר אישי ולשינוי קצר מול המורה. אין להפיק commits ריקים כדי לעמוד במכסה. נלמדים clone, status, diff, stage, commit, pull, push והיסטוריה. PR, merge ותכנון ענפים אינם יעדי הקורס. בתקלת סנכרון עוצרים ופונים למורה בלי Force Push ובלי מחיקת עבודה.

## איך בנויה הדרכה

כל פרק מתחיל בתוצאה שניתן לראות, מסביר מעט מושגים, מציג קובץ חדש או diff עם הקשר, ומסתיים בהרצה, בדיקות ומשימה אישית. הערות בקוד ותיעוד summary מסבירים כוונה; תשתיות מסומנות כמוכנות. לא נדרש לשנן Dependency Injection, async או כתיבת parser כדי לערוך תוכן, אך גם לא מציגים אותן כאילו התלמיד כבר למד אותן ב־C#.

Markdown הוא תוכן חובה: תלמיד כותב מאמר ומבין את מקורו. Mermaid הוא תרשים שניתן לקרוא, להסביר ולתקן. שימוש ב־AI מיועד לניפוי שגיאות; סוכן פעיל אינו כותב את הפרויקט. GEMS יפותחו לאחר שהמורה יעבור על ההדרכות וייצב אותן. אין משימות הנדסת פרומפטים במסלול הקוד.

## היקף הנתונים וההרחבות

מתחילים ב־Animal עם מזהה, שם, תיאור Markdown ונתיב תמונה מקומית. מוסיפים Keeper וקשר אחד־לרבים בלבד. פרק 13 מציג את הקשר; פרק 13א מתרגל CRUD למטפלים. חיות קיימות אינן נמחקות במעבר: משייכים להן מטפל דרך הטופס. אין טבלת מינים, קשר רבים־לרבים, העלאת קבצים או דרישת שרת SQL.

Identity נוסף אחרי CRUD למסד חשבונות נפרד. בעלות על רשומה נפרדת מהמטפל העסקי. רשומות ישנות ללא בעלים נשארות לקריאה; לא מעניקים אותן אוטומטית למשתמש הראשון. פרסום באינטרנט, ניהול admin ומחיקת חשבונות אינם חלק מההגשה. Google הוא רשות בלבד; הכניסה המקומית נשארת זמינה.

## הכנה להרצה אחרי Clone

```shell
dotnet tool restore
dotnet restore RazorTaba
dotnet build RazorTaba
dotnet ef database update --context AppDbContext --project RazorTaba
dotnet ef database update --context AuthDbContext --project RazorTaba
dotnet watch --project RazorTaba --launch-profile http
```

הפקודות לעיל מתאימות לגרסה הסופית. לפני פרק 9 אין מסד וכלי EF; בפרקים 9–14 יש רק AppDbContext. Accounts.db ו־AuthDbContext נוספים בפרק 15. קובצי migration עוברים ב־Git, קובצי db וסודות אינם עוברים. לפני EF אין צורך להכין מסד כדי ללמד HTML.

## מה אומת ומה עוד דורש מורה

לכל מעבר רץ בוצעה בנייה ובדיקת HTTP כאשר נוספה התנהגות דף. הליבה נבדקה גם בטפסים אמיתיים וב־Chromium למחשב וטלפון, כולל Mermaid תקין ופגום. בדיקות הסיום כוללות שני משתמשים, הרשאות, קלט שגוי ושדרוג מסד. פרטי האימות המעודכנים נמצאים ב־`docs/verification.md` במאגר המורה.

ההדרכות נשארות במצב טיוטה עד סקירת המורה. לא פורסמו קישורי ניווט חדשים באתר. כניסת Google מלאה דורשת אישורי OAuth אמיתיים; בדיקת ההפניה לבדה אינה בדיקת התחברות מלאה.
