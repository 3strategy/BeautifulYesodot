זו נקודת עצירה שנתית תקפה: אתר אישי עם תוכן ו־CRUD. את ההרחבות אפשר ללמוד בהמשך בלי לשנות את רף הליבה.

קישורי GitHub מפנים למאגר פרטי. המורה צריך להעניק הרשאת קריאה; אפשר ללמוד גם מהקוד המופיע כאן.

## מה נלמד

- לבדוק התנהגות ולא רק צילום מסך.
- להציג התקדמות באמצעות היסטוריית Git.
- לבצע שינוי עצמאי ולתאר מה גרם לתוצאה.

## מתחילים מסונכרנים

פתחו את תיקיית הפרויקט הנכונה, בדקו שאין שינוי לא שמור והפעילו **Pull**. אם Git מציג התנגשות, פנו למורה; אל תמחקו עבודה ואל תבצעו Force Push.

## חוזרים למסלול הקצר

פתחו את רשימת הבדיקה המצורפת. עברו עליה בזוגות: אחד מבצע ואחד מתעד תוצאה צפויה ותוצאה בפועל. בדיקת Python היא כלי למורה ואינה דרישת התקנה לתלמידים. היא מפעילה טפסים אמיתיים עם cookies ואסימון האבטחה.

התקציב הוא בסיס תמיכה, לא תקרת העשרה. מי שטרם השלים עיצוב ממשיך עם Bootstrap הפשוט ומקבל זמן לחיזוק. לפני Identity מריצים מקומית; הרשאות עריכה עדיין לא נוספו.

## השינויים בקוד

### `docs/core-assessment.md`

קובץ חדש. צרו את `docs/core-assessment.md` והדביקו את התוכן הבא:

````markdown
# בדיקת הגשת ליבה

- האתר אישי, קריא ונגיש ברוחב טלפון. עיצוב עשיר אינו תנאי להמשך בנתונים.
- יש מאמר Markdown ותרשים Mermaid שהתלמיד יכול להסביר ולתקן.
- יוצרים, מציגים, עורכים ומוחקים רשומה; קלט לא תקין אינו נשמר.
- מפעילים מחדש ובודקים שהרשומה נשמרה.
- התלמיד מבצע שינוי קטן בפני המורה ומסביר את זרימת GET/POST.
- בודקים לפחות 50 commits משמעותיים לאורך השנה, תאריכים ותוכן שינויים.
- אין חובה ל־Identity או פרסום באינטרנט בנקודת העצירה הזו.
- לפני שיעור Identity הפרויקט מיועד להדגמה מקומית בלבד: פעולות CRUD פתוחות.
````

## מריצים ובודקים

1. צרו, ערכו ומחקו רשומה; בדקו גם קלט שגוי.
2. צרו רשומה נוספת, עצרו והפעילו שוב ובדקו שנשמרה.
3. הציגו מאמר ותרשים במחשב ובטלפון.
4. הראו למורה היסטוריית commits ושינוי עצמאי קצר.

## משימה אישית ובדיקת הבנה

בחרו תיקון קטן שעלה בבדיקה, בצעו אותו והציגו diff לפני commit. אין ליצור עשרות commits ריקים כדי לעמוד במכסה.

{: .box-success}
בסיום שינוי משמעותי: בדקו את ה־diff, בצעו Stage, כתבו הודעת commit שמתארת מה שיניתם, ובצעו Push. ודאו ב־GitHub שהשינוי הגיע. נדרשים לפחות 50 commits משמעותיים לאורך השנה, גם למי שעובד תמיד באותו מחשב נייד.

{: .box-note}
AI יכול לעזור להבין הודעת שגיאה ולנפות תקלה. אתם אחראים לכתוב, לבדוק ולהסביר את הקוד; אין להפעיל סוכן שיכתוב את הפרויקט.
