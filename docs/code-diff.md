# Side-by-side word diffs in lessons

Use the `code_diff` Liquid block for small edits that are obscured by whole-line
red/green replacements. It generates static HTML during the Jekyll build, using
the existing Ruby runtime with no added gems, browser library, or network request.

```liquid
{% code_diff %}
 public static void PrintSummary(int count, int total)
 {
-    WriteLine(count);
-    WriteLine(total);
+    Console.WriteLine(count);
+    Console.WriteLine(total);
 }
{% endcode_diff %}
```

Each context line starts with one space, removed when rendered. Removed lines
start with `-`; added lines start with `+`. Preserve source indentation after that
prefix. Blank lines are allowed. Supply a focused excerpt without Git headers or
`@@` hunk markers. Put Liquid tags at column zero, outside Markdown fences.

The renderer reconstructs both versions, removes their shared indentation,
aligns similar lines, then compares words, whitespace, and punctuation. Only the
changed tokens get `<ins>` or `<del>` markup. For `Console.WriteLine`, the insertion
is **`Console.`**, while `WriteLine` stays unmarked. Independent changes on one line
are highlighted separately. Identifiers are treated as words: renaming an
identifier marks that identifier, rather than individual letters inside it.

Before (`לפני`) appears on the left and after (`אחרי`) on the right, using the
shared `two-columns before-after` convention. Comparisons intentionally remain
side by side at every width, overriding the shared mobile stacking rule. This is
a wide-screen teaching view; a narrow viewport scrolls horizontally rather than
breaking the correspondence between lines. Add `full-width: true` to comparison pages. Each panel
scrolls horizontally and is keyboard focusable; code is never wrapped or shrunk
to force long lines into a narrow panel. Line numbers are excerpt-relative and
generated by CSS; they are not part of the source text. Copying source does not
include diff markers. Alignment gaps are empty lines, not source changes.

The intentionally neutral code color makes the actual edit stand out. Green
underlining marks additions; red strikethrough marks removals. Both themes have
dedicated colors, and the HTML remains readable without JavaScript. This is a
teaching-excerpt renderer, not a Git patch viewer: it does not recognize renames,
moved blocks, patch metadata, or file line numbers. Use ordinary highlighted diff
blocks for large structural changes where a unified diff is clearer.

Implementation: `_plugins/code_diff.rb`, `assets/css/code-diff.css`. The existing
`==prose==` preprocessor skips these blocks so it cannot change code comparisons.

Validation:

```sh
bundle exec ruby tests/code_diff_test.rb
bundle exec jekyll build --unpublished
npx playwright test tests/code-diff.spec.js --workers=1
bundle exec jekyll build
```

The browser tests use `tests/fixtures/code-diff.md`, an unpublished C# example
rendered with this site's actual layout and CSS. The final normal build removes
that fixture from the output; do not publish a build made with `--unpublished`.
Tests cover light/dark themes, exact word highlights, line alignment, clean
copying, permanent side-by-side placement, and JavaScript-disabled rendering.

## Keeping the sibling sites aligned

Ported from BeautifulMivney on 16 September 2026. Keep `_plugins/code_diff.rb`,
`assets/css/code-diff.css`, and `tests/code_diff_test.rb` identical between the two
repos when fixing shared behavior. Browser fixtures and examples may be local
to each curriculum. Update `_plugins/highlight.rb` with focused edits so its
prose highlighter skips `code_diff` and `highlight` blocks. Preserve site-specific
navigation, JavaScript helpers, and other styling when syncing.
